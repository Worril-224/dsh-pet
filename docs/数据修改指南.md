# 直接修改数据指南（重启不被重置）

> 运行中的 Harness 会在内存里持有角色数据，并定期写回磁盘。**改数据前先退出 Harness**，改完再启动；运行中直接改，很可能被下一次写回覆盖。

## 1. 先分清三类文件

> 下文用「数据目录」指运行时数据根目录：默认是 `$DSH_PET_DATA_DIR`，未设置时为 `~/.dsh/dsh-pet/companion-data`。
> 仓库里的 `companion-data/` 只是示例数据，可用 `node scripts/init-data.mjs` 复制到数据目录后再改。

| 类型 | 位置 | 重启会不会被重置 |
|---|---|---|
| **运行时角色数据**（要改的） | `<数据目录>\characters\ophelia\` | 不会，除非文件缺失/校验失败/被脚本或维护任务重写 |
| **bundle 默认模板** | `<repo>\companion-bundle\data\`、`DEFAULT_*` 常量 | 只用于“首次创建”或“重新生成”，改它通常不影响已有角色 |
| **Harness / 插件配置** | `<repo>\companion-bundle\cordis.patch.yml`、`%USERPROFILE%\.dsh\profiles\<profile>\cordis.patch.yml` | 会保留；改后重启生效 |

## 2. 运行时数据路径

以示例角色 `ophelia` 为例：

```text
<数据目录>\characters\ophelia\
├── character.json                 # 角色显示名/描述/排序（可直接改）
├── persona\
│   └── persona.json               # 唯一生效的人设（可直接改，最常改）
├── memory\
│   ├── short-term.json            # 短期记忆
│   ├── long-term\layer-1..7.json  # 长期记忆
│   ├── meta.json / index.json     # 内部索引，不建议手改
│   ├── events.jsonl               # 维护事件日志，不建议手改
│   └── 记忆总览.md                # 自动生成，手改会被重写
├── life\
│   └── day-plan-YYYY-MM-DD.json   # 每日生活计划（可直接改；见下方格式）
└── qq\
    ├── sessions.json              # QQ 最近对话缓存（插件会重写，不要手改）
    └── status.json                # 心跳/状态（插件每秒级重写，不要手改）
```

### 人设

只改：

```text
<数据目录>\characters\ophelia\persona\persona.json
```

- 这个文件存在时，bundle 重装、Harness 重启、Host 维护都**不会覆盖**它；
- 不要改 `companion-bundle\data\persona.default.json`，那只是首次创建时的模板；
- 不要运行 `import-persona.mjs --overwrite` 等会覆盖人设的脚本；
- 改前备份，改完重启 Harness。

### 每日生活计划（life）

只改：

```text
<repo>\companion-data\characters\ophelia\life\day-plan-YYYY-MM-DD.json
```

格式示例：

```json
{
  "version": 1,
  "dateKey": "2026-11-09",
  "characterId": "ophelia",
  "generatedAt": "2026-11-08T04:06:46+08:00",
  "source": "nightly-memory-maintenance",
  "events": [
    {
      "id": "evt-1",
      "time": "20:40",
      "title": "读完一篇文章",
      "type": "阅读",
      "content": "晚上读完最后几章，把书合上，灯还亮着。",
      "sourceType": "life",
      "sentAt": null
    }
  ]
}
```

- `time` 必须是 `HH:mm`；
- `events` 数量必须在 2–7 个之间（新计划默认 5–7 个）；
- `content` 不能超过 600 字，`title` 不能超过 40 字；
- `id` 不能重复；
- `sentAt` 用 `null`（未发）；发送后插件会写发送时间；
- `type` 可选，值必须是：`日常 / 回忆 / 阅读 / 外出 / 休息 / 整理 / 料理`；
- `sourceType` 可选，值必须是：`memory / web / life`；
- **JSON 写坏、字段缺失、事件数不在 2–7、时间不是 HH:mm，都会被判定为无效并重新生成**，看起来就像“被重置”；
- 重启后 `ensureDayPlan` 只在“当天没有有效计划”时生成；已有有效计划会保留。凌晨 4:00–6:00 的维护只生成“次日”计划，已有有效计划会跳过。

### 记忆

只改：

```text
<数据目录>\characters\ophelia\memory\short-term.json
<数据目录>\characters\ophelia\memory\long-term\layer-N.json
```

但强烈建议：

1. **先完全退出 Harness**，否则内存里的旧数据会盖掉你的修改；
2. 先复制备份；
3. 只改 `items` 里已有条目的字段，不要改 `id`、`layer`、`mentionedAt` 等内部字段；
4. 改完用 JSON 工具校验；
5. 如果只是想让角色“记住一件事”，优先在 Web GUI 让她调用记忆工具写入，或通过 `memory_note` 记录，而不是手改 JSON。

`meta.json`、`index.json`、`events.jsonl`、`记忆总览.md` 是引擎派生的，不要手改。

### QQ 对话缓存/状态

不要手改：

- `qq\sessions.json`：插件会按 `historyLimit` 截断并重写；
- `qq\status.json`：插件定期写心跳。

要改“她记得最近聊过什么”，改 `memory`，不是改 sessions。

## 3. 为什么你改完重启会被重置

按常见原因排序：

1. **Harness 还在运行时改了记忆/会话/状态文件**：插件下一次写回会用内存态覆盖磁盘；
2. **改的是默认模板/源人设卡**（`companion-bundle/data/persona.default.json`、导入用的人设卡 JSON）：运行时根本不读它们；
3. **life 计划 JSON 写坏了**：校验失败 → 当天/次日计划被重新生成；
4. **改的是 `sessions.json`/`status.json`**：插件会重写；
5. **跑了会覆盖的脚本**：`import-persona.mjs --overwrite` 等会覆盖人设的脚本；
6. **凌晨维护刚跑过**：4:00–6:00 会维护记忆并生成次日计划；在这之前改“次日计划”且文件无效会被重建。

## 4. 安全修改流程

```text
1. 退出 Harness（确认托盘/进程都退出）
2. 备份整个 ophelia 目录，或至少备份要改的文件
3. 用 UTF-8 编辑 JSON，保持字段类型正确
4. 用 JSON 校验（PowerShell：Get-Content xxx.json -Raw | ConvertFrom-Json）
5. 启动 Harness
6. 看 qq/status.json、life/day-plan-*.json 是否保留你的修改
```

## 5. 配置类修改（不属于角色数据）

- QQ 联网/回复长度/气泡数/生活分享开关：
  `<repo>\companion-bundle\cordis.patch.yml` 的 `companion-qq.config`；
- Harness 全局默认模型/推理等级：
  `%USERPROFILE%\.dsh\profiles\<profile>\cordis.patch.yml`；
- 这些文件重启后保留；改完需要重启 Harness（或重装 bundle）才生效。

如果某个文件一重启就恢复，先确认你改的是**上表中“运行时数据”路径**，而不是默认模板或派生文件。
