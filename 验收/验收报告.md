## 二、验收方法与证据

1. **开发者测试**：`node scripts/run-tests.mjs all`（Node 内置 `node:test`）。每个测试使用 `fs.mkdtempSync` 临时目录，不读写示例数据目录。
2. **独立验收测试**：`node 验收/verification/run-verification.mjs`。验收员按 SPEC 与验收标准重新设计断言，不引用开发者测试代码；全部使用临时目录 + 假时钟/假 socket/假 LLM。
3. **行为演示**：`node 验收/脚本/acceptance-demo.mjs`。固定时钟推进 10 天，逐阶段打印中文状态并断言（11 个阶段）。
4. **安装与静态核对**：bundle 安装后在 profile 中可见 `companion-host` / `preset-companion` 行；数据目录按角色生成；bundle 零 npm 依赖、所有 import 仅 `node:*` 与包内相对路径。
5. **文档与实现一致性**：SPEC / README / 操作手册 / bundle patch 与实现行为交叉核对（DEV-02 / DEV-04 / DEV-05 / RL3 / PP1 等用例）。

## 四、验收中发现并修复的问题

| 编号 | 问题 | 修复 | 复验 |
|---|---|---|---|
| BUG-01 | 情绪自动抽取把时间词硬编码为「今天」 | 使用捕获到的原文时间词；关键词同步 | 原失败用例 + 4 组时间词断言通过 |
| DEV-01 | 自动抽取批量新增后只检查一次短期容量 | 每新增一条立即检查溢出 | 容量边界回归通过 |
| DEV-02 | SPEC 未定义 `checkMaintenance` 首次运行分支 | 补充 SPEC 4.9 | 文档一致性用例通过 |
| DEV-03 | `host.js` 未导出 `inject = []` | 已导出 | 断言通过 |
| DEV-04 | QQ `buildReplyPayload` 返回形态与 SPEC 字面不一致 | SPEC 6 改为描述实现形态 `{ endpoint, method, body }` | 文档一致性用例通过 |
| DEV-05 | README 声称 `memoryConfig.decayDays` 可覆盖但实现不支持 | 文档改为「衰减阈值固定 1/3/7/14/30/140 天」 | 文档与实现一致性用例通过 |
| RISK-01 | preset 消息监听未过滤非用户来源 | 增加 `source.kind` 过滤（非 user 跳过） | 3 组过滤用例通过 |
| QV4 | QQ 发图后模型「看不到图」：`saveImages` 的 `data` 传了 base64 字符串，真实契约要求 `Uint8Array` | 改为 `new Uint8Array(bytes)`；`imageCount` 取实际 refs 数 | 契约断言 + 多模态消息用例通过 |
| OBS-VOICE-1 | 语言风格参考示例偏短，展开能力不足 | 示例扩写到 120 字以上 | 复验通过 |

仍保留的低风险项：工具 JSON Schema 未声明 minItems/maxItems（执行层已夹取，行为正确）；digest 长期命中过滤后条目可能少于上限（设计如此，不阻塞）。

## 五、公开版变更说明（相对原项目）

公开版删除了只服务原作者本机环境的一次性脚本与私有数据，验收范围相应调整，**核心模块与断言未削弱**：

| 类别 | 原项目 | 公开版处理 |
|---|---|---|
| 一次性人设/记忆改写脚本 | `apply-ophelia-story-canon.mjs`、`rewrite-persona-immersive.mjs`、`refine-persona-voice.mjs`、`adjust-persona-dialogue-style.mjs` 等 | 不随仓库提供；对应 `story-canon.test.js`、`voice-style.test.js` 已移除；效果固化在示例人设中 |
| 私有故事数据集 | 48 条《闭馆之夜》/《菲尼克斯》记忆 + `pending-seed` | 换成 30 条虚构示例记忆（短期 8 + 长期 22）；对应数据集断言改为示例数据断言 |
| 真实账号与主机路径 | 真实 QQ / appId / openid / B 站 UID / 本机绝对路径 | 全部替换为示例值（`123456789` / `10001` / `1234567890` / `OPENID_EXAMPLE` / `12345678`），数据目录改为 `DSH_PET_DATA_DIR` 或 `~/.dsh/dsh-pet/companion-data` |
| 原始输出快照 | `验收/输出/`、`验收/独立验收报告.md` | 已删除（含真实聊天与账号数据）；复验请直接跑命令 |

## 六、未自动验证 / 范围外（如实说明）

1. **真人对话体验**：语气、人设一致性、`persona_lookup` 的实际调用意愿依赖模型行为，需在 Web GUI 选择「情感陪伴 · 奥菲莉亚」预设后人工体验。
2. **预设真机挂载**：预设行已注册、模块可解析；「选择预设 → 挂载子插件树 → 注入 system prompt」需新建会话触发。
3. **QQ 真机联调**：OneBot/官方网关均在假 socket/假 fetch 下验证；真实 NapCat 登录、官方机器人 openid 审批需按 `docs/QQ接入-*.md` 手工完成。
4. **B 站扫码登录**：登录流程为集成测试 + 页面核对；真实扫码与评论区发送需自行配置账号。
5. **本地 ComfyUI 生图**：生成链路为假服务测试；真实出图依赖本机 ComfyUI 与模型文件。
6. **M11 自动接线**：`handleContextPressure`（按重要度保留一半）已在引擎层实现并通过测试；尚未与 Harness 真实上下文压缩事件接线。
7. **外部服务依赖**：联网检索、B 站、生图未配置时对应功能自动跳过，不影响聊天。
